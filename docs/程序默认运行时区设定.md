## 1. 程序默认运行时区设定

解决不同程序，数据库部署的系统时区配置差异，导致程序之间获取的时间的不一致性。针对运行程序设置默认的运行时区。

### 1.1 设置SpringMVC框架代码jackson的格式化的默认时区:

> [!note]
>
> 这里配置的是框架自带的Jackson格式刷的ObjectMapper的时区属性

`````yaml
 spring:
   jackson:
     time-zone: ${user.timezone:Asia/Kolkata}
     date-format: yyyy-MM-dd HH:mm:ss.SSS
`````

### 1.2 自定义构建ObjectMapper对象的时区在默认不设置的时候，采用的是UTC的时区进行格式化处理的。

> [!note]
>
> 注意时区需要按需设置

```
    ObjectMapper mapper = ObjectMapper();
	mapper.setTimeZone(TimeZone.getDefault());
    mapper.setDateFormat(new SimpleDateFormat("yyyy-MM-dd HH:mm:ss.SSS"));
```

### 1.3 程序启动过程设置默认运行时区：

```
import java.util.TimeZone;

    // 定义默认时区变量
    private static final String runtimeTimeZone = "Asia/Kolkata";

    public static void main(String[] args) {
        // 设置默认运行时区
        setDefaultTimeZone();

        // ... 其他代码
        SpringApplication.run(XXXXApplication.class, args);
    }

    // 程序启动设置运行时区
    private static void setDefaultTimeZone() {
        System.setProperty("user.timezone", runtimeTimeZone);
        TimeZone.setDefault(TimeZone.getTimeZone(runtimeTimeZone));
        log.info("####====> 设置程序运行时区: {}", TimeZone.getDefault().getID());
    }
```

## 2. 接口以及数据时间的使用

> [!note]
>
> 数据库timestamp转换到Date字段会根据默认session的时区拼接, 需要做时区转换.
>
> Java对象中，建议使用Instant对象接收数据库是timestamp类型的字段.

* 如程序需要给前端返回时间戳（秒/毫秒）程序转换方式：

```

Date dt = new Date();           // 默认时间格式化跟, 程序时区&数据库跟session时区一致
Long timestamp = dt.getTime();  // 拿到的时UTC的时间戳

```

* 如果是LocalDateTime则需要转换为UTC时间:

```

LocalDateTime dt = LocalDateTime.now();
Long timestamp = dt.toEpochSecond(ZoneOffset.UTC)

```
